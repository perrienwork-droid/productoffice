Search bar — component reference

All rules governing the search bar, dropdown, pills, and related interactions on the library homepage.

1. Anatomy

Visual stack (top → bottom)
Search input wrap
↓
Search hint
↓
Topic pills (hidden by default)
↕ overlays on top ↕
Search dropdown (absolute positioned)

Inside the search input

The input wrap (.search-input-wrap) is a flex container. It holds two types of children:

HTML Phrase pills — one per locked search phrase, rendered inside #searchPhrasePills. Each pill has a × remove button.

HTML Text input — the actual <input> element. Fills remaining space via flex:1.

Outside the search input

HTML Clear button (.search-clear) — absolute-positioned inside .search-box, appears when input has content.

HTML Search hint — "Press Enter to lock a phrase · Use comma to add another". Dismissed permanently after first phrase is locked (localStorage).

HTML Topic pills row (.search-pills-wrap) — horizontally scrollable row of 24 pre-validated topic shortcuts. Hidden by default, revealed on focus.

HTML Search dropdown (.search-dropdown) — absolute-positioned below the input, overlays everything. Contains structured results.

2. States & transitions

StateTriggerWhat changes
Idle Default / blur with empty input No shadow. Pills hidden. Dropdown hidden. Placeholder visible.
Focused onfocus on input Soft shadow appears on input. Pills row slides open (max-height transition). Dropdown still hidden until 2+ chars typed.
Typing oninput, value ≥ 2 chars Dropdown opens with live results. showSearchDropdown(q) called on every keystroke.
Phrase locked Enter key or comma Text → phrase pill inside input. Input cleared. Dropdown dismissed. applyFilters() runs. Pills row stays visible. Card grid filters.
Multi-phrase Lock additional phrases Multiple pills stack inside input wrap (flex-wrap). Placeholder changes to "Add another phrase…"
Blur (with phrases) onblur, phrases exist Pills row stays visible. Shadow stays. search-focused class retained.
Blur (empty) onblur, no phrases, empty input Pills row collapses (200ms delay). Shadow removed. search-focused class removed.
Cleared Click × clear button All phrases removed. Input emptied. Dropdown hidden. Pills row collapses. All cards restored to tier grids. search-focused removed.

3. Search logic

Core function: searchDeep(q)

Single shared function used by both the dropdown preview and the persistent section results below the card grid. Guarantees identical results in both locations.

JS Input: raw query string q

JS Output: { groups: [...], solves: [...] }

JS Data source: SEARCH_INDEX — loaded from search-index.js. Contains all topics with their sections, methods, and keywords.

Matching algorithm

JS Query is split into content words via getContentWords() — strips stopwords, punctuation, and short tokens.

JS Each word is matched against the haystack using fuzzyWordMatch() — a word-based substring/prefix match, not semantic.

JS Fallback: if no fuzzy match found, tries Levenshtein distance ≤ 1 for typo tolerance.

Scoring

Match typePointsMeaning
Topic-level hit10Query matches the topic's title/keywords
Section hit3 (each)Query matches a section title/keywords within the topic
Method hit2 (each)Query matches a method name/keywords within the topic

Groups are sorted by total score descending — more matches rank higher.

Card relevance scoring (within search results grid)

SignalPointsExample
Title exact match+50Searching "Product Marketing" → card titled "Product Marketing"
Title contains phrase+30Searching "product" → card titled "Product Marketing"
Phrase in title+20Phrase found in h3 title text
Phrase in title+desc+10Phrase found in title or description
Phrase in keywords only+3Phrase found in data-topic or solves, not title/desc

Cards within each tier (exact / also relevant / partial) are sorted by this relevance score.

4. Dropdown structure

The dropdown renders three groups, in order:

GroupLabelContentCap
1"matches your need"Solves hits — teal badge, direct problem matchesNo cap
2"topics"Topic-level matches — disc prefix + topic name + disc badge6 topics
3"sections & methods"Section/method hits grouped under parent topic. Type badges (THEORY, PRACTICAL, METHOD, EXAMPLES). Anchor links.8 topic groups

UX Group labels have padding: 10px 20px 4px — aligned with the 20px left padding of result items.

CSS Dropdown has border-radius: 10px, border: 1px solid var(--ink), and wide blurry shadow: 0 8px 40px rgba(26,23,20,0.15), 0 2px 12px rgba(26,23,20,0.08).

CSS max-height: 400px; overflow-y: auto — scrolls internally.

Dropdown interactions

JS Clicking a topic result: navigates to the topic page.

JS Clicking a section/method result: navigates to topic page with anchor.

JS Clicking a "solves" result: locks the phrase (same as pressing Enter).

JS Dropdown is dismissed when: phrase is locked, input is cleared, or focus leaves the search area.

5. Topic pills

UX 24 validated pills. Every pill has been tested against the full card haystack using the same getContentWords → fuzzyWordMatch logic. All 24 return 1–9 card results.

CSS Hidden by default. Pills wrap has max-height: 0; overflow: hidden; opacity: 0. Revealed via .search-focused class on parent.

CSS Transition: max-height 0.25s, opacity 0.2s, margin 0.25s

CSS z-index: 2 — sits above search bar shadow but below dropdown (z-index: 200).

CSS Style: border-radius: 999px (full pill), border: 1px solid var(--ink-hairline), horizontal scroll with fade gradient on right edge.

Pill visibility rules

ConditionPills visible?

Input blurred, phrases activeYes (stays open)

6. Card grid behavior when searching

JS Cards move from their original tier grids into a flat #searchResultsGrid.

JS Cards are bucketed into three tiers based on match quality:

Tierdata-search-tierConditionVisual
Exact1All phrases match in title+descFull opacity, no label
Strong2All phrases match, some in keywords onlyFull opacity, "Also relevant" label above
Partial3Only some phrases matchDimmed (opacity 0.55), "Partial matches" label

Within each tier, cards are sorted by relevance score (title exact match > title contains > desc match > keyword match).

Heading above card grid

CSS TOPICS MATCHING "X" · N results — shown when search phrases are active.

CSS Style: 11px uppercase, hairline after. Class .search-heading.

Persistent section results below card grid

JS Calls same searchDeep() function — identical results to dropdown.

UX SECTIONS MATCHING "X" · N results heading. Flat list, no cap (dropdown caps at 8 groups).

CSS One row per hit: section name + type badge + parent topic name. Hairline separators, hover highlight, anchor links.

CSS Overflow protection: text-overflow: ellipsis, min-width: 0, flex-shrink on name/topic columns.

Restoring cards on clear

JS Each card stores its original tier grid ID in data-orig-tier before moving.

JS On clear: cards are moved back to their original #tier-N .topic-grid container.

JS Tier labels and search heading are removed.

7. Docked filter bar (replaces dual search inputs)

On desktop, when the user scrolls past the hero, the entire filter bar (search + pills + tier links) is reparented into the nav bar. There is no separate nav search input.

JS dockFilterBar() moves the filter bar element into .nav-inner and adds class .docked + .scrolled on the nav.

JS undockFilterBar() reverses: moves filter bar back to page flow, removes classes.

JS A placeholder div preserves the original height to prevent layout jump.

JS On mobile (≤768px), docking is skipped entirely — the filter bar stays in page flow.

CSS Scrolled nav flips to page colors (background: var(--paper)). Logo becomes vertical: 44×44 mark on top, "The Black / Book" in two lines below (Playfair Display 900, 11px).

JS syncSearch() still exists but syncs the single input with card grid filtering, not two separate inputs.

8. Subpage nav search

Every topic page has a search input in the nav bar (#navSearchInput inside .nav-search-box) alongside four discipline pill buttons (UX, PM, MK, CS).

JS Discipline filtering. Pill buttons toggle activeDiscs state (same interaction as homepage: single-click toggles, double-click isolates). Search results from topicNavSearch() are filtered by active disciplines before display.

HTML Pills are <button> elements with data-disc attribute and onclick="toggleDisc('xx')".

CSS On mobile (≤768px): disc pills are hidden, search + theme toggle + burger all equalized to 40px height. Search expands on focus (hides nav title temporarily via .search-expanded class).

JS The burger panel has its own independent search (#burgerSearchInput) which does NOT filter by discipline — it always searches all topics.
